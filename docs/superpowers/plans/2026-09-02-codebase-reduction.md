# Codebase reduction plan — why R+ is 637,000 lines and how to get it to ~230,000

**Date:** 2026-09-02 · **Author:** Claude (Fable plan; 17 read-only auditors + 34 adversarial verifiers + 1 senior ranker, all Sonnet/Opus) · **HEAD:** `4e537c37` · **Status:** executed 2026-09-02 on branch `chore/codebase-reduction` (cursor + claude), uncommitted; task status in `PLAN.md` `{#shrink}`

> Short answer: **No, the app does not need half a million lines.** 58% of the repo is committed build output. Of the ~176,000 hand-written lines, roughly 26,000 are dead, duplicated, retired, or content-as-code, and the rest is spread across 2–4× more files than the concepts need. The plan below removes **~410,000 lines** (of which ~380,000 are build output) with zero behavior change in the first two phases, then changes the rules that caused the growth so it does not come back.

## 2. Why it got this big — root causes with evidence

### R1. Build output is committed (372k + 4k + 3k lines, 58%)
- `scripts/build-cloud-mobile.mjs` writes the mobile bundle into `cloud/sync-pages/public/mobile/`, which `cloud/sync-worker/wrangler.toml` serves via `[assets] directory = "../sync-pages/public"`. It was committed (commit `d9c08c6f`) so `wrangler deploy` works from a checkout. `cleanDest()` wipes and rebuilds the directory on every run, but old chunk files were committed along the way: 191 of 479 chunk files are unreferenced by the current `app.bundle.meta.json`.
- `scripts/build-equipos-pages.mjs` copies `public/equipos` → `cloud/equipos-pages/public/equipos`. 61 tracked files are exact byte duplicates of another tracked file.
- `public/index.html` is generated (`<!-- generated by build-ui; edit index.src.html -->`) but tracked because `prestart` runs `bundle-renderer` and not `build-ui`, so `npm start` relied on the committed copy. CI and `prebuild:mac/win` already regenerate it.
- The desktop equivalents (`public/js/app.bundle.mjs`, `public/js/chunks/`, `public/styles/app.bundle.css`) are already gitignored — the rule exists, it was never applied to the cloud copy. No CI check asserts that a build script's output directory is ignored.
- Git archaeology: the mid-July 46 MB spike was an AI code-understanding tool's cache JSON committed for weeks and purged in `5554a0fc` (−1,191,545 lines) — resolved. After July, 26.5 MB of the 29.8 MB growth is the mobile bundle.

### R2. A metric ratchet rewarded splitting files instead of deleting code (the whole shape of `public/js`)
- `eslint.config.mjs` (Tier 1 = all of `public/js` and `lib`): `complexity: 15`, `max-lines-per-function: 80`, `sonarjs/cognitive-complexity: 20`. `scripts/metrics/constants.mjs`: `MAX_FILE_LINES = 600` (2 debt points per 10 lines over). `npm run metrics:check` fails any change that raises `totalScore` above `baseline.json` (306).
- The response is visible in history: `c9c1b793 refactor(debt): Tier 1 clean — god-file splits + complexity burn-down` (541 files touched, **471 created**, +69,559 / −60,156), `30fc61a7 chore(debt): burn down technical debt score to 0 (770 → 0)`, `d797f8af Step 4b: Extract closeReleaseNotes…`, `db5cb0f9 Step 5: Extract inferFechaLabSetFromId to a leaf module`. **All 10 debt burn-down commits are net LOC-positive: +97,645 / −77,992 = +19,653 lines.** Two one-off assembler scripts (`scripts/assemble-settings-help-split.mjs`, `scripts/assemble-platform-split.mjs`) exist only to glue split files back together and now read input files that no longer exist.
- Result: 972 source files, **447 under 100 lines**, average 156. Suffix families: `-modal` 33, `-render` 25, `-html` 22, `-state` 20, `-ui` 18, `-helpers` 17, `-core` 15, `-bridge` 12, `-runtime` 10. Sixteen file families have 10+ files; `estado-actual-*` is **78 source files / 12,872 lines** for one panel (13 of them carry the header comment "extracted from X.mjs"); `teams-roster-*` 32; `panel-admin-*` 21; `lib/clinical-scope/evaluate/` is 19 files for 583 lines (one is 2 lines, a re-export "to keep the import surface stable").
- The split tax is measurable: of 6,215 exported symbols in `public/js` + `lib`, **2,298 are imported by exactly one other file**, **771 by nobody**, **626 only by tests**. Import/export boilerplate alone is 5,338 lines. 857 `import()` sites exist.
- Splitting created cycles: `dependency-cruiser` reports **1,182 distinct import cycles touching 469 of 2,480 modules**; the longest is 82 modules (`tend-group-analyte-picker` → `tend-export` → `tendencias-event-context` → `app-state` → `clinical-repo-hydrate` → `db-storage-bridge` → `clinical-access-runtime` → …). The repo's own `no-circular` rule is configured and never gated. Six "bridge" objects of empty functions (`estado-actual-panel-runtime.mjs`, `lab-panel-runtime-state.mjs`, `settings-help/bridges.mjs`, `settings-help/tour-bridge.mjs`, `med-pharm-profile-bridge.mjs`, `tendencias-bridge.mjs`) exist to be monkey-patched at import time so the cycles load.
- Net effect: every file *looks* small while the total grew. The code was never made smaller — it was spread thinner. (The boot-graph debt rule, `BOOT_GRAPH_DEBT_PER_IMPORT = 25` on three hub files, is correctly scoped and is **not** the culprit — keep it.)

### R3. Two runtimes, hand-synced copies
- `public/js/clinical-ops-bundle-merge.mjs` (489 lines) vs `lib/db/clinical-ops-bundle-merge*.cjs` (666 lines) — same algorithm, different file boundaries, already diverged. `public/js/clinical-username.mjs` ↔ `lib/db/clinical-username.mjs` — header says "Renderer mirror", each has functions the other lacks. `clinical-privileges.mjs` twins with drifted docs. `equipos-cloud-mode.mjs` in three places, `dom-escape.mjs` in three. jscpd: 133 exact clones (2,107 lines) inside source alone.
- This is unnecessary: esbuild already bundles `lib/*.mjs` into the renderer — 8 `public/js` files import from `../../lib/` today. The "keep in sync with X" comment convention has failed in 3 of the 4 places it is used.

### R4. Retired features left as fossils
- LAN LiveSync was retired in 8.0.5 and the 7.9 Nube cutover is finished, yet: the cutover wizard (13 files, 1,233 lines) checks `/^7\.9/` against version 8.2.9; three one-shot "retire" runners still execute on every boot; `server.js` (406 lines, dev-only behind an env var) + `lib/interno/interno-router-*` (10 files) + `lib/equipos/equipos-router-*` (8 files) = 2,163 lines with zero tests, still shipped in the installer because `build.files` includes `lib/**`; `clinical-conflict-viewer` (11 files, 914 lines) is a LAN-era conflict UI nothing opens; `lab-eventualidad-interpret.mjs` (597 lines) reads exactly like the north-star lab-interpretation step and is unreachable.
- Verified dead-by-reference: **~45 files / 5,930 lines** in `public/js` + `lib` (full list in §5, move 5). The test manifest keeps them green in CI forever, giving false confidence.
- Traps for a name-based sweep: `lib/db/lan-db-bridge.cjs` is the live app-wide DB-manager singleton; half of `lib/electron-lan-cors.cjs` is live Nube CORS; `public/interno/` and `public/equipos/` are the live sources of the cloud deploys; 9+ `.lan-*` CSS classes back the live Nube QR-pairing panel.

### R5. Content shipped as code
- `data/release-notes-highlights.mjs` (3,796 lines, 284 versions back to 2.0.0) is in the eager boot bundle **and** named explicitly in `build.files`; `getCuratedReleaseNotes()` reads only the current version's key, so every other entry is unreachable forever. `CHANGELOG.md` (2,925 lines, stuck at 7.4.0 since 2026-06-22) and `README.md` (935 hand-written lines of version history) duplicate `docs/RELEASE_NOTES_*.txt` (the real source, 148 files).
- Nube "fix guides", diagnostics prose, tour scripts, two parallel demo-patient seed systems (tour vs pitch), `docs/demos` + `docs/mocks` (5,228 lines of stale preview HTML), two unused pitch JSON bundles (1,550 lines).

### R6. Tests that pin shape, and a hand-maintained manifest
- 682 test files (74k lines). `package.json scripts.test` lists all 685 paths literally (31,267 chars); `scripts/lib/test-manifest.test.mjs` fails when a new test is not added; its walker misses `.test.cjs`, so `lib/labs/lab-panel-overlay-lww.test.cjs` has never run. 49 test files read source as text: a few are sound guards (no new globals on `app-state.mjs`), most assert a function body's regex or a file's line count (`app-shell-exports.test.mjs` asserts ≤ 800 lines). Merging two files fails tests that never tested behavior. `app-boot-imports.test.mjs` carries 131 lines of per-release prose justifying 21 budget raises.

### R7. Docs an agent must read before a first edit
- `CLAUDE.md` 138 lines, `AGENTS.md` 81, `README.md` 999, `PLAN.md` 242, `MISTAKES.md` 118, 8 `.cursor/rules/*.mdc` (455 lines), `docs/core/` 21 files, handoff 245, `design.md` 104. `AGENTS.md` and `documentation-sync.mdc` give two different "read first" orders; `agents-base.mdc` restates the AGENTS.md ladder and has drifted from it. The code map `project-context.mdc` — named by `CLAUDE.md` as the thing to load — is **gitignored**, so a fresh clone or any git worktree (which `CLAUDE.md` tells agents to spawn) has no code map. `docs/superpowers/` (all plans and specs, including this file) is gitignored too.

## 3. Does the app need this much code? No.

- 58% is build output that should never have been in git. Removing it changes nothing for users.
- Of the ~176,000 hand-written lines, the audit verified about **26,000** as removable without a product decision: dead files 5,930, dead tooling 2,018, ward server 2,163, release-notes data 3,400, docs/demos + pitch JSON 6,790, dead CSS 2,728, release-history triplication 3,860, unwired oxlint + manifest 2,382, exact twins ~900. Another ~1,650 (cutover wizard, ABG-extended code behind a flag hard-coded `true`) waits on a product decision.
- The bigger win for AI agents is not lines but **files**: folding single-fan-in splits and barrels takes ~1,240 source modules toward ~900–1,000 and cuts "files to open for one change" from 6–10 to 2–3 in the worst slices (cloud-sync, clinical access, tendencias, DB persistence).
- Honest end state for the product as it exists today: **~227,000 tracked lines** (from 637,000), **~150,000 hand-written**, tests discovered by glob, zero committed build output. The remaining code is live; further cuts need feature retirements (pitch mode, LAN dev server, ABG-extended) that only the owner can call.

### The spaghetti, named

The code is not spaghetti in the classic sense (huge tangled functions). It is the opposite failure — **confetti**: concepts cut into many tiny files to satisfy size rules, then glued back with re-export barrels, bridge objects, runtime-injected stubs and dynamic imports.

1. **Barrel chains.** `tendencias.mjs` → `tendencias-core.mjs` → `tendencias-ui.mjs` → real file. `features/clinical-teams.mjs` (1 line) → `clinical-teams/index.mjs` → `teams-roster.mjs` → real file. `mutate-bridge.mjs` re-exports three siblings. Half the files on a trace contain no logic.
2. **Split-by-suffix families.** `estado-actual-*` 78, `teams-roster-*` 32, `panel-admin-*` 21, `med-receta-*` 15, `lab-panel-*` 14, `tend-group-*` 12. 2,298 exports exist only so one other file can import them.
3. **Cycle-breaking stubs.** Six bridge objects of empty functions overwritten at import time. Grep for the implementation lands on a no-op. 1,182 cycles remain anyway.
4. **String coupling.** 163 `onclick="name"` attributes, 22 `window.*` handlers, 17 `globalThis.__RPC_*` flags, `getElementById('tour-dock')`-style ids across tour files, CSS selectors built by concatenation. No tool connects them; the module graph is not the reference graph.
5. **Twins.** Merge algorithm, username rules, privileges, equipos helpers, dom-escape, cultivo parsing, reference ranges, patient-header fill. Three pairs have drifted; one drift already lost data silently (`medCatalog` in SQLCipher mode).
6. **Fossils with live-sounding names — and live code with dead-sounding names.** `lab-eventualidad-interpret.mjs` (dead), `clinical-conflict-viewer` (dead), `cutover-flags.mjs` (dead branch) vs `lan-db-bridge.cjs` (live singleton), `electron-lan-cors.cjs` (half live), `.lan-connect-card` (live Nube UI).
7. **Tests that pin shape.** 49 tests read source as text; merging two files fails tests that never tested behavior.
8. **Content as code.** Release notes, fix guides, diagnostics prose, tour scripts, demo seeds.

## 6. Rules to change so it does not come back

1. **Delete `MAX_FILE_LINES = 600` and `fileLineOverageDebt`** (`scripts/metrics/constants.mjs`, `score.mjs`). Replace with a **total tracked-LOC ratchet that only goes down** (repo-wide and per top-level dir) and a **module-count ratchet that only goes down**. Today a 700-line file costs debt, so it becomes two 350-line files and the score improves while the repo grows.
2. **Remove `max-lines-per-function: 80`** from ESLint tier 1. It is the direct cause of the "extracted from X.mjs" files and the suffix families. **Keep** `complexity: 15` and `sonarjs/cognitive-complexity: 20` — they measure behavior, not size, and do not reward moving lines to a new file. **Keep** the boot-graph debt rule as is.
3. **CI check: no build script may write a tracked file.** For each of `build-ui.mjs`, `bundle-renderer.mjs`, `build-cloud-mobile.mjs`, `build-cloud-interno.mjs`, `build-equipos-pages.mjs`, assert every path under its output dir passes `git check-ignore`. This one rule would have prevented the 372,211-line commit.
4. **CI check: no two tracked files may be byte-identical** outside an allowlist (61 pairs today). Retire the "keep in sync with X" comment convention: either one shared module under `lib/shared/` or a parity test — never a comment.
5. **Test discovery by directory, not manifest** (move 12). Delete the drift guard.
6. **Ban new structure-pinning tests**: a `*.test.mjs` may not `readFileSync` a `.mjs/.js` source path unless on an explicit allowlist (`app-state-deprecation`, `app-boot-imports` export-name checks, `clinical-p5-gate-progress`). Rewrite or delete the other ~45 as they block merges.

8. **One docs entry point.** Track the code map (`!.cursor/rules/` after the `.cursor/` ignore line, or move it to `docs/core/`) — a gitignored code map is invisible to every worktree and clone. ## 7. Target architecture for AI agents

End state ≈ **227,000 tracked lines**, ~900–1,000 source modules, no generated output tracked.

```
public/js/
  app.js  app-runtimes.mjs  app-shell.mjs  app-state.mjs  dom-escape.mjs   ← only cross-feature primitives stay flat
  features/<feature>/                                                         ← one dir per clinical feature, 3–8 files each
     estado-actual/  tendencias/  labs/  cloud-sync/  clinical-teams/  expediente/  entrega/  eventualidades/ …
lib/
  db/  clinical-repo/  doc-generators/  drive-import/  lab-repo/            ← main-process Node only; never imports public/js
  shared/                                                                     ← the ONE home for logic both processes need (.mjs, no .cjs twins):
     clinical-username.mjs  clinical-ops-bundle-merge.mjs  lab-reference-ranges.mjs  clinical-privileges.mjs
cloud/<worker>/src/                                                           ← Worker source only; cloud/*-pages/public is gitignored output
scripts/                                                                      ← build, release, metrics; no one-shot ticket scripts
docs/core/ (≤ 20 files) + docs/RELEASE_NOTES_*.txt                            ← plus ONE tracked code map
```

- **File-size norm:** 300–800 lines per cohesive module. A concept is one file — no `-html/-render/-state/-paths/-decisions/-wire/-apply` slicing, and no file whose only importer is the file it was split from. 800+ lines is an advisory to reconsider the boundary, not a CI failure. Barrels only with 3+ external consumers; a barrel over a barrel is never allowed.
- **Tests:** colocated `*.test.mjs`, discovered by directory. No `tests/` mirror, no manifest. Structure-pinning tests capped at an explicit allowlist.
- **Docs an agent reads:** exactly two entry points — `docs/core/00-system-index.md` and a tracked code map. `CLAUDE.md` and `AGENTS.md` point at those two and nothing else. One release-history source.
- **Reference graph, not import graph, is the deletion gate:** because of 857 `import()` sites, 163 inline `onclick` names, 22 `window.*` globals and 17 `__RPC_*` flags, dead-code checks must grep the full tracked corpus by stem, never rely on AST import analysis alone. Always use `git ls-files` as the corpus, never a filesystem walk from `.` (stale worktrees on disk).

## 9. Risks and mitigations

- **Nube mobile deploy on a fresh clone** finds no assets → Phase 0 ships `predeploy` **and** `predev` hooks before any gitignore lands; the deploy script asserts `mobile/index.html` exists.
- **Release pipeline**: `release-git.js` already skips ignored paths; `updateReadme()` throws if README's version block changes shape — preserve it; never touch `stable-versions.json` (117 live entries) or `min-version.json`.
- **SQLCipher migrations**: `SCHEMA_VERSION` is 26 and the v1→v26 chain runs on every open with a 6.4.0 floor — do not squash it; rewrite the two `schema.test.mjs` blocks that use `enqueueLanSyncOutbox` with raw inserts.
- **docx templates** are binary and in `build.files` — never reformat; decide `sexo` casing before extracting a shared helper.
- **CSS sweep by prefix** would kill the live Nube pairing UI — exact selectors only, per-token checks.
- **Structure-pinning tests** will fail on behavior-preserving merges — grep touched basenames across `*.test.mjs` for `readFileSync` first; a passing but irrelevant test is not evidence.
- **Concurrent worktrees** corrupt evidence — always scan `git ls-files`, and the new test runner passes explicit dirs.

## 10. Method

Scouting: `git ls-files` + `wc -l` by extension/dir; esbuild metafile diff (`public/js/app.bundle.meta.json`, `cloud/…/app.bundle.meta.json`) for bundle membership; import-graph script (1,241 files, 4,677 edges); export-usage script (6,215 exports); `jscpd` (`--min-tokens 60`); `dependency-cruiser` (2,480 modules); CSS class-token cross-reference; `git log --numstat` archaeology. Then a 52-agent workflow: 17 slice auditors (Sonnet, read-only), 2 adversarial verifiers per slice (runtime/dependency lens and product/test lens), 1 ranking critic (Opus). Every LOC figure above was computed with `wc`, not estimated; every refuted claim (pitch-mode deletion, prefix-based CSS sweep, several fan-in counts) was dropped or corrected. Raw outputs: session scratchpad `maps.json`, `verifies.json`, `critic.json`.
